# bazzfin

A single custom **Fedora Atomic / bootc** image: a desktop-free Universal
Blue base with the **NVIDIA (open) driver**, the **Hyprland** Wayland
compositor and the **ly** display manager baked in, plus every application,
font, Flatpak, dotfile and Homebrew package needed at first login -- ready
to boot straight into a working Hyprland session.

It's built with [BlueBuild](https://blue-build.org) on top of the
desktop-free `ghcr.io/ublue-os/base-main` image. The whole build is
described declaratively in [`recipes/recipe.yml`](recipes/recipe.yml); the
`Containerfile` is generated by BlueBuild's CLI/GitHub Action, not maintained
by hand.

---

## What is baked in

- **Bazzite's "ogc" gaming kernel** (Open Gaming Collective), staged from
  `ghcr.io/ublue-os/akmods:ogc-44` and swapped in the same way Bazzite's own
  build does it (`files/scripts/install-ogc-kernel.sh`; versionlocked for
  the remainder of the build only). If Secure Boot is on, enroll the akmods
  signing key once with `ujust enroll-secure-boot-key`.
- **NVIDIA (open) driver** via the `akmods` module (`base: ogc`,
  `nvidia-driver: nvidia-open`), plus `xone`/`xpadneo` kmods; the module
  also injects the nouveau-blacklist / `nvidia-drm.modeset` kernel
  arguments itself.
- **Kernel command-line tuning** via the `kargs` module
  (`bluetooth.disable_ertm=1`, for some Bluetooth controllers).
- **ZRAM tuned like Bazzite**: zstd, `min(ram/2, 16 GiB)`
  (`files/system/etc/systemd/zram-generator.conf`).
- **HDR/gamescope userspace bits**: Bazzite's patched `gamescope` (from the
  `bazzite-org/bazzite` COPR), `VK_hdr_layer` (from `ublue-os/staging`) and
  `egl-wayland`. (Hyprland's own HDR/VRR support is per-monitor config, not
  an image-level toggle.)
- Hyprland from the `lionheartp/Hyprland` COPR, `ly` on tty2, the Fedora
  package list, Brave/VS Code/zed from their own repos,
  Obsidian/Zotero/Pyprland from upstream releases, Nerd/Google fonts,
  chezmoi dotfiles (`aahsnr-configs/dots`), and a curated Homebrew CLI
  toolset.

See [`recipes/recipe.yml`](recipes/recipe.yml) for the authoritative,
commented list -- it's shorter and easier to read than a changelog here.

## Repository layout

```
.
├── recipes/recipe.yml            # The whole build, declared as BlueBuild modules
├── files/
│   ├── dnf/                      # Local .repo files for the `dnf` module
│   ├── justfiles/                # ujust recipes shipped in the image (`justfiles` module)

│   └── system/                   # Copied verbatim to `/` by the `files` module
├── .github/
│   ├── workflows/build.yml       # Builds and publishes the image on GitHub

├── Justfile                      # Local build/lint helpers (wraps `bluebuild`)
└── cosign.pub                    # Public key for verifying the image
```

## Setting up the GitHub repository (first time)

These steps take the repo from zero to a working CI build. They assume
`git` and the [GitHub CLI](https://cli.github.com) (`gh`, authenticated
with `gh auth login`) are installed, and that
[cosign](https://github.com/sigstore/cosign) is installed.

> **Order matters.** Pushing to `main` automatically triggers the build
> workflow, and the build **signs the image** with a private cosign key read
> from a repository secret. That secret (`SIGNING_SECRET`) **must be added
> before the workflow can start** — so follow the steps in order: create the
> repo, add the signing secret, and only then push.

### 1. Create the repository (don't push yet)

```bash
# Explicitly use `main` as the initial branch: the build workflow only
# triggers on pushes to `main`, and step 4 pushes that branch.
# (Older git versions: use `git init`, then `git branch -M main` later.)
git init -b main
git add -A
git commit -m "Initial BlueBuild recipe"
# (If the commit fails with "Please tell me who you are", set your
#  identity first: git config --global user.name / user.email)

# Create the GitHub repo (name it `bazzfin`) and wire up the remote,
# WITHOUT pushing yet -- the push happens in step 4, after the signing
# secret exists:
gh repo create bazzfin --public --source . --remote origin
# ...or make it private if you prefer:
# gh repo create bazzfin --private --source . --remote origin
```

### 2. Generate the cosign signing key pair

The image is signed with [cosign](https://github.com/sigstore/cosign) so
machines can verify it before rebasing. If you don't have a key pair yet,
generate one (this creates `cosign.key` + `cosign.pub` in the repo root):

```bash
# COSIGN_PASSWORD="" makes cosign skip the password prompt entirely and
# write an UNencrypted private key -- exactly what GitHub Actions needs.
COSIGN_PASSWORD="" cosign generate-key-pair
```

> **IMPORTANT — the key must be UNencrypted.** The private key is used
> inside GitHub Actions, and an encrypted key **will not work**. The
> `COSIGN_PASSWORD=""` command above guarantees that. If you instead run
> plain `cosign generate-key-pair`, do **not** enter a password when prompted
> — just press Enter. If you accidentally set a password, delete both files
> and regenerate before continuing. (Per the
> [BlueBuild cosign guide](https://blue-build.org/how-to/cosign/).)

- **`cosign.key`** (private) must never be committed — it's already listed
  in `.gitignore`. Keep it safe; losing it means images can't be signed with
  that identity anymore.
- **`cosign.pub`** (public) _is_ committed at the repo root — machines
  running this image use it to verify rebases.

> If you already have an existing, **unencrypted** key pair (e.g. carried
> over from a previous image), reuse it — just make sure the committed
> `cosign.pub` is the public half of the private key added in the next step,
> otherwise signature verification on rebase will fail.

### 3. Add the signing secret — required before GitHub Actions can start

The build workflow signs the image with cosign and reads the **private key
from a repository secret named `SIGNING_SECRET`**. The value of that secret
is the **entire contents of the `cosign.key` file**. It must be in place
_before_ the first workflow run, or the build will fail.

Add it either way:

**Via the GitHub web UI** (repo must already exist, so run this after step 1):

1. Open your repository's **Settings**.
2. In the sidebar, pick **Secrets and variables** → **Actions**.
3. Click **New repository secret**.
4. **Name:** `SIGNING_SECRET`
5. **Secret:** open `cosign.key` in an editor and **copy-paste its entire
   contents** (the PEM block) into the value field.
6. Click **Add secret**.

**Via the GitHub CLI** (run from the repo root — `gh` resolves the repo via
the `origin` remote added in step 1):

```bash
gh secret set SIGNING_SECRET < cosign.key
```

Confirm it's registered:

```bash
gh secret list
# NAME             UPDATED
# SIGNING_SECRET   about x seconds ago
```

> If you already pushed and the first run failed with a cosign/signing
> error, that means the secret was missing or the key was encrypted — fix it
> here, then re-run the workflow from the **Actions** tab (**Re-run jobs**)
> or with `gh run rerun`.

Nothing else is needed — the workflow's `GITHUB_TOKEN` already has the right
permissions (`packages: write`, `id-token: write`) declared inline.

### 4. Push and run the first workflow

Now that the secret exists, push — this automatically triggers the first
build (documentation-only changes are ignored):

```bash
git push -u origin main
```

Or trigger it manually at any time:

```bash
# From the CLI:
gh workflow run build.yml --ref main

# Then watch it:
gh run watch
```

Or in the browser: **Actions → bluebuild → Run workflow**.

> The first build takes a while (often 30–60+ minutes: akmods NVIDIA driver
> build, COPR installs, fonts, Homebrew, …). Subsequent builds are usually
> faster thanks to GitHub Actions caching done by the BlueBuild action.

### 5. Verify the published image

When the run finishes successfully, the image is published to
[GHCR](https://ghcr.io) as:

```
ghcr.io/<your-github-username>/bazzfin:44     # tag = recipe's image-version
ghcr.io/<your-github-username>/bazzfin:latest
```

Check it — any of these works:

- **Browser (easiest):** the package appears in the repo's sidebar under
  **Packages**, and on your profile under **Packages → bazzfin**.
- **Inspect from a container host:**
  ```bash
  # Not needed if the package is public; required for private packages:
  podman login ghcr.io
  skopeo inspect docker://ghcr.io/<your-github-username>/bazzfin:latest
  ```
- **Verify the signature:** cosign reads registry credentials from the
  container login above, so log in first for private packages:
  ```bash
  cosign verify --key cosign.pub \
    "ghcr.io/<your-github-username>/bazzfin:44"
  ```
  (CLI-only alternative for listing tags:
  `gh api "user/packages/container/bazzfin/versions"` — note that the
  packages API needs an extra scope, grant it with
  `gh auth refresh -s read:packages` first.)

> GHCR packages start **private**. To let anyone pull the image without
> authenticating, go to your GitHub profile → **Packages → bazzfin →
> Package settings → Change visibility → Public** (or keep it private and
> `podman login ghcr.io` on target machines).

### 6. Deploy / rebase a machine onto it

```bash
sudo bootc switch ostree-image-signed:docker://ghcr.io/<your-github-username>/bazzfin:44
systemctl reboot
```

Or `ujust rebase` on a machine already running this image.

## Building locally

Install the [BlueBuild CLI](https://blue-build.org/how-to/local/), then:

```bash
just validate   # check recipes/recipe.yml against the schema
just generate   # print/save the generated Containerfile
just build      # build the image with podman/buildah
just switch     # build, then rebase this machine onto it
just lint       # shellcheck the build scripts
```

## CI

`.github/workflows/build.yml` builds the image via
[`blue-build/github-action`](https://github.com/blue-build/github-action) on
push to `main`, on pull requests, and on a daily cron, and signs it with
[cosign](https://github.com/sigstore/cosign) using the `SIGNING_SECRET`
repository secret (the **full contents of `cosign.key`** — see the setup
steps above). The matching public key is committed as
[`cosign.pub`](cosign.pub).
